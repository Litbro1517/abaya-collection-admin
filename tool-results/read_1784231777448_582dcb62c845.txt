    21→    21→## [SYSTEM_FLOW]
    22→    22→
    23→    23→### Flux 1 : Chargement du catalogue public
    24→    24→1. Utilisateur visite `/` → `page.tsx` (client-side)
    25→    25→2. `CatalogPreview` monté → Zustand lit `catalog` (cache localStorage)
    26→    26→3. Si pas de cache → `GET /api/catalog` → sections + config
    27→    27→4. Pour chaque section visible → `GET /api/datasources/{id}?mode=meta` (colonnes) + `GET /api/datasources/{id}/rows?limit=200` (lignes)
    28→    28→5. `ColorMap` chargée → `GET /api/colormap` → résolution hex des color dots
    29→    29→6. Rendu : chaque carte produit lit `config.titleColumn`, `config.priceColumn`, `config.colorColumn`
    30→    30→
    31→    31→### Flux 2 : Saisie couleur (WRITE-side)
    32→    32→1. Admin ouvre DataTable → `ColorCell` sur une ligne
    33→    33→2. Toggle/select couleurs → mise à jour locale `rowData[colSlug]`
    34→    34→3. `PUT /api/datasources/{id}/rows/{rowId}` → persistance en base
    35→    35→4. Alternatives : ColorSourceModal (import masse) ou quick-add (ColorMap + auto-select)
    36→    36→
    37→    37→### Flux 3 : Changement de langue
    38→    38→1. Utilisateur clique Globe → sélection FR/EN/AR
    39→    39→2. `useAppStore.setClientLocale(loc)` → Zustand + localStorage
    40→    40→3. `useClientTranslation` re-render → `t()` utilise le nouveau locale
    41→    41→4. `ThemeInjector` update `<html dir="rtl|ltr">` + `<html lang="fr|en|ar">`
    42→    42→
    43→    43→### Flux 4 : Tunnel de commande (COD)
    44→    44→1. CTA "Commander" → `CheckoutPage` (formulaire nom/tél/ville/adresse)
    45→    45→2. `POST /api/orders` → création Order en base
    46→    46→3. Redirect `/merci?order_id={id}` → recap + bouton "Retour au catalogue" (`href="/"`)
    47→    47→
    48→    48→### Flux 5 : Upload logo/favicon (admin)
    49→    49→1. Admin clique bouton upload dans SettingsPillar → `ImageUpload` / `ImageUploader` composant
    50→    50→2. `POST /api/upload` (FormData avec fichier image)
    51→    51→3. **Branche A** (SUPABASE_URL + SUPABASE_ANON_KEY présentes) → upload vers bucket `assets/branding/` → URL publique Supabase
    52→    52→4. **Branche B** (clés absentes ou upload Supabase échoué) → fallback local `public/uploads/` → URL relative `/uploads/{filename}`
    53→    53→5. Réponse format strict : `{ data: { url, filename } }` → composant UI met à jour le champ settings
